# AI Gateway V1

بوابة محلية خفيفة وآمنة (Zero-Trust Local Reverse Proxy) متوافقة تمامًا مع واجهة OpenAI، مبنية على FastAPI وSQLite وDocker. صُممت البوابة لتعمل كوسيط معزول بين تطبيقات العميل ومزودات نماذج اللغة الكبيرة (LLMs) مع حماية قصوى للأسرار والبيانات.

---

## المزايا والقدرات الفنية

- **نقاط نهاية متوافقة مع OpenAI:**
  - فحص الجاهزية والصحة: `/healthz`.
  - استعراض النماذج المتاحة: `/v1/models`.
  - إكمال المحادثات: `/v1/chat/completions` (بالنمط العادي المباشر JSON أو التدفقي المتزامن SSE مع دعم كامل لـ `stream_options`).
- **أمان مفاتيح العملاء (Zero-Trust Key Management):**
  - توليد مفاتيح عشوائية تشفيرية عالية القوة (256-bit CSPRNG).
  - تخزين المفاتيح كـ HMAC-SHA-256 مع خلطها بسِر خادم فريد (Server Pepper).
  - حماية من هجمات التوقيت (Timing Attacks) بحساب تعمية وهمي ثابت الزمن للطلبات المرفوضة.
  - إلغاء فوري للمفاتيح، وتحديد سقف معدل الطلبات بالدقيقة (RPM) مخزن ومقفل ذريًا في SQLite.
- **حماية استباقية من SSRF وعزل الشبكة:**
  - حظر النطاقات والشبكات الخاصة (RFC 1918)، والـ Loopback، وعناوين الربط المحلي والبيانات الوصفية السحابية (RFC 3927 / AWS / GCP / Azure `169.254.169.254`)، وشبكات الـ CGNAT (RFC 6598).
  - تثبيت الاتصال المباشر بالـ IP المحلل (Pinned IP Transport) لمنع هجمات DNS Rebinding.
- **الحماية من هجمات رفض الخدمة (DoS Protection):**
  - سقف أقصى لحجم طلب العميل (1MB عبر `BoundedBodyMiddleware`).
  - سقف أقصى لتدفق ردود المزود غير التدفقية (10MB) لحماية الذاكرة من نفاد الحجم (OOM).
- **التراجع التلقائي وإعادة المحاولة (Reliability & Fallbacks):**
  - تراجع تلقائي إلى مزود ثانوي بديل عند حدوث أخطاء محددة (429 أو 5xx أو انقطاع الاتصال) بحد أقصى محاولتين بشرط عدم بدء تدفق أول بايت للعميل.
- **تخزين آمن وترقيات آلية للمخطط:**
  - قاعدة بيانات SQLite مفعلة بنمط WAL وFULL synchronous ومهلة قفل 5 ثوانٍ.
  - ترقيات آلية للمخطط معتمدة على `PRAGMA user_version`.
  - تسجيل بيانات وصفية وإحصائية فقط (طوابع زمنية، أزمنة استجابة، استخدام التوكنز) دون تسجيل الرسائل أو نصوص المحادثات أو الأسرار مطلقًا، مع فترة احتفاظ 30 يومًا ونسخ احتياطي حي عبر `scripts/backup.sh`.

## التثبيت والتشغيل السريع

### 1. المتطلبات
- Docker وDocker Compose (أو بايثون 3.12+ لبيئة التطوير المحلية).

### 2. التهيئة وتوليد الأسرار
شغّل سكربت التهيئة لتوليد قيمة Pepper تشفيرية عشوائية داخل ملف `.env` (لا تُطبع القيمة على الشاشة):

```bash
chmod +x scripts/*.sh
./scripts/init_env.sh
```

### 3. إعداد المزودات
انسخ القالب التجريبي واضبط مزوداتك ونماذجك الحقيقية:

```bash
cp config/config.example.yaml config/config.yaml
```

عدّل `config/config.yaml` وحدد اسم متغير البيئة للمفتاح (مثل `OPENAI_API_KEY`)، ثم أضف المفتاح الفعلي إلى `.env`:

```bash
echo "OPENAI_API_KEY=sk-your-real-key" >> .env
chmod 0600 .env
```

### 4. التشغيل عبر Docker Compose
يتم تشغيل الحاوية داخل شبكة جسر خاصة (`gateway_internal`) مع ربط صارم لمنفذ المضيف على `127.0.0.1:8000`:

```bash
# فحص تكوين Compose
docker compose config

# بناء وتشغيل الحاوية في الخلفية
docker compose up -d --build
```

### 5. التحقق من الصحة المحلية
```bash
./scripts/health_check.sh
```

## إدارة مفاتيح العملاء (Admin CLI)

تتم إدارة المفاتيح محليًا عبر سطر الأوامر دون فتح أي واجهة عامة، مع دعم التصدير بصيغة JSON للأتمتة البرمجية:

### إنشاء مفتاح عميل جديد:
```bash
docker compose exec -T gateway python -m app.admin create-key --name "app-frontend" --rpm 60
```
> يُعرض السر الخام **مرة واحدة فقط**؛ احفظه مباشرة في مدير أسرار آمن.

### استعراض العملاء المسجلين:
```bash
docker compose exec -T gateway python -m app.admin list-clients --json
```

### استعراض استهلاك عميل معين:
```bash
docker compose exec -T gateway python -m app.admin usage <client_id> --json
```

### إلغاء صلاحية مفتاح عميل فورًا:
```bash
docker compose exec -T gateway python -m app.admin revoke-key <client_id>
```

### النسخ الاحتياطي لقاعدة البيانات:
```bash
./scripts/backup.sh
```

## الاختبارات وفحص الجودة

يحتوي المستودع على حزمة اختبارات مؤتمتة متكاملة تشمل اختبارات الوحدة، والتكامل، والأمان، وفحص سلسلة التوريد:

```bash
# تشغيل كامل حزمة الاختبارات المحلية
.venv/bin/python -m pytest -q
```

- **حالة الاختبارات الحالية:** **105 passed** (مع تخطي 39 اختبارًا خاصًا ببيئة Linux/POSIX وصلاحيات الحاويات عند التشغيل على نظام Windows).
- **أمان سلسلة التوريد:** متطلبات الإنتاج في `requirements.lock` مثبتة بالهاش المشفر (`--require-hashes`)، ومتطلبات التطوير مفصولة في `requirements-dev.lock`.
- **الفحص الأمني الساكن:** تغطية كاملة ضد ثغرات Bandit (0 High)، واختبار ساكن يفرض ربط المنفذ على `127.0.0.1` ويمنع أي تعريض عام للشبكة.
