# AI Gateway V1

بوابة محلية خفيفة بواجهة متوافقة مع OpenAI، مبنية على FastAPI وSQLite. ملفات المشروع، ونصوص التشغيل، وملف Docker Compose، والاختبارات مشمولة ومتبعة بالكامل في المستودع.

> [!NOTE]
> في بيئة التدقيق الحالية (Windows Host)، أمر Docker غير مثبت محلياً؛ لذلك لم تُشغّل الحاوية أو يُفتح أي منفذ على المضيف، وجرى التحقق عبر اختبارات Python المؤتمتة ومحاكاة النقل.

---

## ما الذي يفعله الإصدار

- **نقاط النهاية**: `/healthz` (فحص صحة غير مقيد بمصادقة)، و`/v1/models`، و`/v1/chat/completions` (تدعم الاستجابة العادية وتدفق أحداث SSE).
- **إدارة المفاتيح والمصادقة**: مفاتيح عملاء عشوائية مشتقة بصيغة `gw_<client_id>.<token>`، وتُخزن في SQLite كبصمة مجزأة `HMAC-SHA-256` مع `PEPPER` سري عالي العشوائية (لا يقل عن 32 بايت).
- **حماية التوقيت (Timing Attack Protection)**: تنفيذ عملية تجزئة افتراضية (`_DUMMY_DIGEST`) للعملاء غير المسجلين لتوحيد زمن الاستجابة ومنع تعداد العملاء.
- **إلغاء فوري**: التحقق من حالة الإلغاء لحظياً في كل طلب من قاعدة البيانات مباشرة.
- **تحديد معدل الطلبات (Rate Limiting)**: حد أقصى للطلبات في الدقيقة (RPM) مخزن في SQLite ويُحدّث عبر معاملات ذرية (`BEGIN IMMEDIATE`) مع رأس استجابة `Retry-After` عند تجاوز الحد.
- **التراجع التلقائي (Fallback)**: محاولتان كحد أقصى للتراجع إلى مزود تالٍ في قائمة المزودين عند أخطاء شبكة أو أخطاء خادم محددة فقط (مع منع التراجع بعد بدء تدفق بايتات SSE للعميل).
- **تسجيل آمن**: تسجيل البيانات الوصفية والاستخدام (عدد الرموز والزمن والنموذج) دون تسجيل نصوص الرسائل، أو محتوى المدخلات، أو مفاتيح العملاء، أو أسرار المزودين (تم التحقق عبر اختبار الكناري S5).
- **إدارة إصدارات قاعدة البيانات**: ترقيم المخطط عبر `PRAGMA user_version = 1` مع نظام ترحيل تلقائي يمنع فقدان البيانات.

## الضوابط الأمنية المطبقة (Security Controls)

1. **قائمة سماح لمتغيرات مفاتيح المزودين (F-002)**:
   - يُمنع تماماً استخدام متغيرات البيئة الحساسة مثل `GATEWAY_PEPPER` أو متغيرات النظام (`PATH`, `USER`, `SYSTEMROOT`) كمفتاح لمزود خارجي.
   - يسمح فقط بالبادئات القياسية المعتمدة (`PROVIDER_`, `OPENAI_`, `ANTHROPIC_`, إلخ).

2. **الحماية من هجمات SSRF على عناوين المزودين (F-003)**:
   - فرض بروتوكول `HTTPS` افتراضياً لعناوين المزودين (`api_base`).
   - حظر العناوين المحلية (`localhost`, `127.0.0.1`, `::1`)، ونطاقات الشبكات الخاصة (RFC 1918)، ونطاق بيانات خوادم السحابة (`169.254.169.254`).

3. **سقف لحجم استجابة المزود (F-009)**:
   - فرض حد أقصى لحجم استجابة المزود الخارجي (10 ميجابايت) لحماية الذاكرة من الاستنزاف وهجمات حجب الخدمة.

4. **حماية ملفات الإعداد من التسرب للحاوية (F-005)**:
   - استبعاد ملفات الإعداد السرية `config/*.yaml` من بناء صورة الحاوية عبر `.dockerignore`، مع الإبقاء على النموذج التوضيحي `config/config.example.yaml` فقط.

5. **فصل تبعيات التطوير وسلسلة التوريد (F-007)**:
   - تنقية `requirements.in` و`requirements.lock` للإنتاج من أي حزم اختبار (`pytest` وتوابعها).
   - حصر أدوات الاختبار والتطوير في `requirements-dev.in` و`requirements-dev.lock`.

## التثبيت والتشغيل عبر Docker Compose

الملفات التشغيلية متتبعة في المستودع:
- `docker-compose.yml`: يعرّف ربط المنفذ على `127.0.0.1:8000:8000` لتقييد الوصول إلى المضيف المحلي فقط (Localhost Binding).
- `scripts/init_env.sh`: توليد ملف `.env` و`GATEWAY_PEPPER` عشوائي آمن.
- `scripts/health_check.sh`: فحص نقطة `/healthz` المحلية.
- `scripts/backup.sh`: أخذ نسخة احتياطية آمنة لقاعدة بيانات SQLite باستخدام SQLite Online Backup API.

### خطوات التشغيل:

1. **إنشاء متغيرات البيئة والـ Pepper**:
   ```sh
   ./scripts/init_env.sh
   ```

2. **إعداد المزودين والنماذج**:
   انسخ `config/config.example.yaml` إلى `config/config.yaml`، واضبط المزودات وعناوين HTTPS الخاصة بها، ثم ضع المفاتيح في `.env`.

3. **فحص سلامة ملف Compose**:
   ```sh
   docker compose config
   ```

4. **تشغيل البوابة**:
   ```sh
   docker compose up -d
   ```

5. **التحقق من صحة الخدمة**:
   ```sh
   ./scripts/health_check.sh
   ```

## إدارة مفاتيح العملاء

- **إنشاء مفتاح عميل جديد** (يُعرض المفتاح الخام مرة واحدة فقط على المخرجات):
  ```sh
  docker compose exec -T gateway python -m app.admin create-key --name my-app --rpm 60
  ```

- **استخدام المفتاح**:
  أرسل المفتاح كترويسة `Authorization: Bearer gw_<client_id>.<secret>`.

- **إلغاء مفتاح عميل**:
  ```sh
  docker compose exec -T gateway python -m app.admin revoke-key <client_id>
  ```

- **سرد العملاء ومتابعة الاستهلاك**:
  ```sh
  docker compose exec -T gateway python -m app.admin list-clients
  docker compose exec -T gateway python -m app.admin usage <client_id>
  ```

- **أخذ نسخة احتياطية لقاعدة البيانات**:
  ```sh
  ./scripts/backup.sh
  ```

## نتائج الاختبارات وحالة التحقق

- **مجموعة الاختبارات العامة والمنصية**:
  - `42 passed`: تشمل اختبارات واجهات API، والمصادقة، وتحديد المعدل، والتراجع، وحماية SSRF، وأمان المزودين، وحد حجم الاستجابة، وتجزئة HMAC للمفاتيح المزورة، وترحيلات SQLite، وتأكيد خلو قفل الإنتاج من حزم الاختبار.
- **اختبارات محمل الأسرار الخاصة بـ POSIX (F-006)**:
  - `39 skipped`: خاصة بصلاحيات ملفات POSIX والروابط الرمزية (symlinks) والـ UID/GID، ويتم تخطيها بأمان على Windows وتفعيلها تلقائياً في بيئة Linux والحاويات.
- **اختبار تسرب الأسرار (Canary Test S5)**:
  - اجتاز بنجاح تام (صفر تسريب لمحتوى الرسائل، أو مفاتيح العملاء، أو مفاتيح المزودين في المخرجات أو السجلات أو قاعدة البيانات).
