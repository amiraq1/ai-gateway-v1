# AI Gateway V1

بوابة محلية خفيفة بواجهة متوافقة مع OpenAI، مبنية على FastAPI وSQLite. ملفات المشروع واختباراته جاهزة، لكن **لم تُشغّل الخدمة عبر Compose**: أمر `docker compose` غير مثبت في بيئة التنفيذ الحالية. لم يُفتح أي منفذ، ولم يُفعّل نفق أو رابط معاينة.

## ما الذي يفعله الإصدار

يدعم `/healthz`، و`/v1/models`، و`/v1/chat/completions` بنمط عادي أو SSE. يتضمن مفاتيح عملاء عشوائية، تخزين HMAC-SHA-256 مع Pepper، إلغاءً فوريًا للمفتاح، حدًا لكل عميل في الدقيقة مخزنًا في SQLite، محاولتين كحد أقصى للتراجع إلى مزود تالٍ عند أخطاء محددة، وتسجيلًا آمنًا للبيانات الوصفية والاستخدام من دون نصوص الرسائل أو مفاتيح API.

لا توجد مزودات أو معرفات نماذج مفعّلة افتراضيًا؛ لم تُختبر بيانات اعتماد مزود حقيقي. أضف نقطة OpenAI-compatible ومعرّف نموذج حقيقيًا إلى `config/config.yaml`، واجعل alias مفعّلًا، ومرّر اسم متغير المفتاح في إعداد المزود. ضع المفتاح نفسه في `.env`، ولا تضعه في ملف التكوين أو سجل الأدلة. مثال placeholders موجود في `config/config.example.yaml` ويظل معطلًا.

## التثبيت والتشغيل بعد توافر Docker Compose

نفّذ الأوامر التالية منفصلة وبالترتيب:

1. أنشئ Pepper محليًا؛ لا تُعرض قيمته على الشاشة:

   ```sh
   ./scripts/init_env.sh
   ```

2. راجع مزوداتك ومعرّفات النماذج الفعلية في `config/config.yaml`، وأضف أسرارها إلى `.env` عند الحاجة. لا تفعّل مزودًا قبل التحقق من توافقه ووجهة مشاركة الطلبات.

3. افحص إعداد Compose؛ يجب أن يبقى نشر المضيف على `127.0.0.1:8000`:

   ```sh
   docker compose config
   ```

4. **لا تشغّل `docker compose up` بالنسخة الحالية.** ملف Compose يربط منفذ المضيف على loopback، لكن Uvicorn داخل الحاوية مضبوط على `0.0.0.0` ليتصل به Docker. هذا لا يطابق حرفيًا شرط ربط التطبيق نفسه على `127.0.0.1`، ويحتاج حسم التصميم قبل النشر.

5. افحص الصحة المحلية فقط:

   ```sh
   ./scripts/health_check.sh
   ```

يعرّف Compose ربط المضيف بصيغة `127.0.0.1:8000:8000`، بينما يستمع Uvicorn داخل واجهة شبكة الحاوية على `0.0.0.0`. لم يُشغّل هذا الإعداد. ربط التطبيق حرفيًا على `127.0.0.1` داخل حاوية bridge لا يتصل تلقائيًا بتحويل Docker؛ أي تغيير إلى host networking يقلل عزل الشبكة ويحتاج قرارًا منفصلًا. لم يُفتح منفذ عام أو يُفعّل نفق أو رابط معاينة.

## مفاتيح العملاء والإدارة

إنشاء المفتاح يعرض السر الخام مرة واحدة، لذا شغّله في جلسة محلية موثوقة واحفظ النتيجة في مدير أسرار:

```sh
docker compose exec -T gateway python -m app.admin create-key --name local-app --rpm 60
```

أرسل المفتاح إلى واجهة API كـ`Authorization: Bearer <key>`. لا تُضمّن المفتاح في سجلات أو أوامر محفوظة.

إلغاء مفتاح باستخدام `client_id` غير السري:

```sh
docker compose exec -T gateway python -m app.admin revoke-key <client_id>
```

سرد البيانات الوصفية أو الاستخدام، دون كشف المفاتيح:

```sh
docker compose exec -T gateway python -m app.admin list-clients
```

```sh
docker compose exec -T gateway python -m app.admin usage <client_id>
```

## الإدارة والمصادقة والتشفير (المرحلة الأولى)

- **أول مدير:** يُنشأ من سطر الأوامر فقط، ويُرفض إذا كان مدير موجودًا. تُقرأ كلمة المرور من الطرفية أو من stdin، ولا تُمرَّر كوسيط:

  ```sh
  python -m app.admin bootstrap-admin --username admin
  ```

- **واجهة الإدارة:** `POST /api/admin/login` و`POST /api/admin/logout` و`GET /api/admin/session` و`GET /api/admin/health` و`GET|POST /api/admin/ip-rules` و`DELETE /api/admin/ip-rules/{id}`. تُرسل الجلسة في كوكي `amnabd_admin_session` بخصائص `HttpOnly` و`Secure` و`SameSite=Lax` ومسار `/api`، فيصل الكوكي إلى مسارات الإدارة والمحادثة معًا. معرّف الجلسة الخام لا يظهر في JSON. كوكي CSRF منفصل اسمه `amnabd_csrf_token` بخصائص `Secure` و`SameSite=Lax` ومسار `/api`، وليس `HttpOnly` لأن الواجهة تقرؤه لترسله في الرأس `X-CSRF-Token`. الخادم يقبل القيمة فقط إذا طابق هاشها المخزَّن في SQLite لهذه الجلسة، فلا تكفي قراءتها وحدها. كل طلب يغيّر البيانات يحتاج هذا الرأس. قيمة CSRF تُعاد من `GET /api/admin/session` أو من تسجيل الدخول، ولا تُخزَّن في Local Storage. `GET /api/admin/session` يعيد القيمة نفسها طالما الكوكي يطابقها، فلا تُبطل علامات التبويب الأخرى. يُصدر رمزًا جديدًا فقط إذا غاب الكوكي أو لم يطابق.
- **الحد من تسجيل الدخول:** خمس محاولات فاشلة لكل IP خلال 15 دقيقة، ثم `429` مع `Retry-After`. تُحجز المحاولة في SQLite قبل فحص كلمة المرور لمنع تجاوز الحد بالطلبات المتزامنة.
- **تزامن Argon2:** يُحسب هاش كلمة مرور المدير في مجموعة عمال محدودة خارج حلقة الأحداث، فلا تتعطل SSE أو `/healthz` أثناء الدخول. الافتراضي عمليتان متزامنتان (`ADMIN_PASSWORD_HASH_CONCURRENCY`، المدى 1–8) وطابور انتظار بسعة 8 (`ADMIN_PASSWORD_HASH_QUEUE`، المدى 0–64). إذا امتلأت السعة يُرد `503` بالرمز `login_busy` و`Retry-After: 2`، ولا تُسجَّل محاولة فاشلة لأن كلمة المرور لم تُفحص. تبقى الخانة محجوزة حتى تنتهي عملية الهاش نفسها، حتى لو انقطع طلب الدخول. وكل محاولة تدخل المحجز مرة واحدة فقط، بما في ذلك ترقية الهاش. كل عملية هاش جارية تحجز نحو 64 MiB من الذاكرة (إعدادات Argon2 الافتراضية)، فالتزامن 2 يضيف نحو 128 MiB إلى ذروة كل عامل. الحد مستقل لكل عملية عمل. مع `N` عاملًا يصبح أقصى عدد من عمليات الهاش الجارية `N × التزامن`، وأقصى عدد من العمليات المقبولة (الجارية والمنتظرة) `N × (التزامن + الطابور)`. الـ Dockerfile الحالي يشغّل عاملًا واحدًا، ويمكن رفع العدد بـ `--workers` أو بمتغير `WEB_CONCURRENCY`.
- **قواعد IP:** تنطبق على كل مسارات `/api/admin` بما فيها الدخول. الرفض له أولوية على السماح. إذا وُجدت قاعدة سماح نشطة فلا يُسمح إلا بالعناوين المطابقة. يُرفض أي تعديل يحجب العنوان الحالي بالرمز `409`.
- **`TRUSTED_PROXIES`:** لا تُقرأ ترويسة `X-Forwarded-For` إلا إذا جاء الاتصال المباشر من عنوان مذكور في هذا الإعداد. السلسلة المشوهة من proxy موثوق تُرفض. الافتراضي فارغ.
- **`ADMIN_ALLOWED_ORIGINS`:** إذا كان الوسيط العكسي يغيّر المخطط أو المضيف الذي يراه المتصفح، فضع هنا أصل HTTPS الذي تستخدمه الواجهة. الطلبات التي تحمل `Origin` أو `Referer` من أصل آخر تُرفض.
- **الطوارئ (CLI محلي فقط):**

  ```sh
  python -m app.admin ip-rules list
  python -m app.admin ip-rules disable <id>
  python -m app.admin ip-rules delete <id>
  python -m app.admin ip-rules reopen
  python -m app.admin ip-rules clear --confirm DELETE-ALL-ADMIN-IP-RULES
  python -m app.admin disable-admin <username>
  python -m app.admin revoke-admin-sessions <username>
  ```

  كل عملية تُسجَّل في `audit_logs` بالمصدر `break-glass-cli`. لا توجد نقطة HTTP لهذه العمليات.
- **مفاتيح المزودين المشفّرة:** تُحفظ بـ AES-256-GCM. المفتاح الرئيسي من `GATEWAY_MASTER_KEY` أو `GATEWAY_MASTER_KEY_FILE`، ولا يُكتب في SQLite. تُقرأ القيمة من الطرفية أو stdin، والأوامر لا تعرض القيمة:

  ```sh
  python -m app.admin provider-secret set OPENAI_API_KEY
  python -m app.admin provider-secret list
  python -m app.admin provider-secret rotate
  python -m app.admin provider-secret delete OPENAI_API_KEY
  ```

  إذا وُجد مفتاح مخزَّن ومصدر env أو ملف للاسم نفسه، يفشل الطلب بشكل آمن ولا يُختار أحدهما.
- **واجهة مفاتيح المزودين (HTTP):** `GET /api/admin/provider-secrets` يعيد الاسم والإصدار والتواريخ فقط. `PUT /api/admin/provider-secrets/{name}` يحفظ المفتاح في الجسم `{"api_key": "..."}`، و`DELETE` يحذف المفتاح، و`POST /api/admin/provider-secrets/rotate` يعيد تشفير المفاتيح التي على إصدار قديم. لا تحتوي أي استجابة على المفتاح أو النص المشفّر أو المفتاح الرئيسي. كل تعديل يُكتب في `audit_logs` بالمصدر `api`. التدوير يتم في معاملة واحدة، فإما تُحدَّث كل الصفوف المطلوبة أو لا يتغير شيء. الطلبات التي تغيّر البيانات تحتاج جلسة و`X-CSRF-Token`.
- **حماية الاتصال بالمزودين:** يُسمح بـ HTTPS على المنفذ 443 فقط. تُرفض عناوين الـ metadata وlink-local وmulticast والعناوين غير المعيّنة، ولا يُتبع إعادة التوجيه، ولا تُستخدم proxies من متغيرات البيئة. العناوين الداخلية أو HTTP أو منفذ غير 443 تحتاج إلى `trusted_internal_networks` لذلك المزود فقط.
- **ترقية قاعدة البيانات:** قبل أول ترقية لقاعدة موجودة تُنسخ إلى `<database>.pre-schema-v<N>-<time>.bak` بصلاحيات `0600`. انسخ القاعدة يدويًا أيضًا قبل النشر. الترقية من V4 إلى V5 تضيف جدولي `conversations` و`messages` فقط، ولا تغيّر جداول V1–V4. التراجع إلى الكود القديم (`main`) يعمل على قاعدة V5 دون فقد بيانات، لكن الكود القديم لا يقرأ مفاتيح المزودين المخزَّنة في SQLite، فتختفي النماذج التي تعتمد عليها من `/v1/models` إلى أن يُضبط المفتاح في متغير بيئة أو ملف.
- **متغيرات بيئة جديدة:** `TRUSTED_PROXIES`، `ADMIN_ALLOWED_ORIGINS`، `ADMIN_SESSION_TTL_SECONDS` (افتراضي 28800)، `ADMIN_SESSION_IDLE_SECONDS` (افتراضي 1800)، `ADMIN_LOGIN_MAX_FAILURES` (افتراضي 5)، `ADMIN_LOGIN_WINDOW_SECONDS` (افتراضي 900)، `GATEWAY_MASTER_KEY` أو `GATEWAY_MASTER_KEY_FILE`، `GATEWAY_MASTER_KEY_VERSION` (افتراضي 1)، و`GATEWAY_MASTER_KEY_PREVIOUS` أو `_FILE` مع `GATEWAY_MASTER_KEY_PREVIOUS_VERSION` أثناء التدوير فقط، و`ADMIN_PASSWORD_HASH_CONCURRENCY` (افتراضي 2) و`ADMIN_PASSWORD_HASH_QUEUE` (افتراضي 8).

## المحادثة (المرحلة 2)

المسارات تحت `/api/chat`، وتتطلب جلسة مدير صالحة، وتتطلب ترويسة `X-CSRF-Token` للكتابة. قائمة IP الخاصة بالإدارة لا تُطبَّق على المحادثة. ترويسة `Authorization: Bearer` لا تعمل هنا، ومفتاح الجلسة لا يعمل على `/v1`.

- `GET|POST /api/chat/conversations` و`GET|DELETE /api/chat/conversations/{id}`. كل محادثة تنتمي للمدير الذي أنشأها. طلب محادثة لا يملكها مدير آخر يُرد بـ `404` مطابقًا لطلب معرّف غير موجود.
- `POST /api/chat/completions` بالجسم `{"model", "message", "conversation_id"?, "stream"?, "request_id"?}`. يرسل العميل الرسالة الجديدة فقط. التاريخ يُقرأ من SQLite، ولا يُقبل حقل `history` من العميل. الاستجابة بصيغة OpenAI، وعند `stream: true` تكون SSE متوافقة مع OpenAI وتنتهي بـ `[DONE]`.
- **الحفظ:** تُحفظ رسالة المستخدم أولًا بالحالة `processing`. يُكتب الرد المساعد مرة واحدة فقط، عند وصول البث إلى `[DONE]` بنص غير فارغ. عند فشل المزود أو انتهاء المهلة أو انقطاع العميل لا يُحفظ أي نص رد.
- **انقطاع البث:** إذا انقطع العميل أثناء SSE تُلغى قراءة المزود، وتصبح رسالة المستخدم `cancelled` بالسبب `client_disconnected`. في الطلب غير المتدفق لا يُلغى استدعاء المزود عند انقطاع العميل، فيُحفظ الرد عند اكتماله. ويعيد الإرسال المكرر بالـ `request_id` نفسه الرد المحفوظ دون استدعاء ثانٍ.
- **`request_id`:** من 8 إلى 64 حرفًا من `A-Za-z0-9_-`. الإرسال المكرر بعد اكتمال الرد يعيد الرد المحفوظ مع `replayed: true` دون استدعاء المزود. الإرسال المكرر أثناء المعالجة يُرد بـ `409 request_in_progress` و`Retry-After: 2`. استخدام المعرّف نفسه لنص آخر أو لمحادثة أخرى يُرد بـ `409 request_id_conflict`.
- **الحدود:** الرسالة حتى 32 KiB بعدد بايتات UTF-8، والرد المساعد حتى 256 KiB ويُقطع البث عند تجاوزه. التاريخ المرسل للمزود حتى 40 رسالة أو 120,000 حرف، ويبدأ دائمًا برسالة مستخدم، وتُعلَم الاستجابة بـ `context_truncated` عند القطع. لا يوجد حد معدل خاص بالمحادثة، والحد الوحيد هو الجلسة وسعة المزودين.
- **ترتيب الرسائل:** تُرتَّب الرسائل حسب الجولة التي بدأتها، وداخل الجولة الواحدة تأتي رسالة المستخدم قبل الرد. لا يُرتَّب الأمر بـ `created_at` وحده، فبهذا لا يسبق رد متأخر رسالة لاحقة.
- **التخزين كنص عادي:** نصوص المحادثات (`messages.content`) تُحفظ في SQLite دون تشفير. احمِ ملف القاعدة وكل نسخة احتياطية منه بالصلاحيات نفسها. لا تدخل النصوص في `audit_logs` أو `request_logs` أو سجلات التطبيق. حذف المحادثة يحذف رسائلها ويكتب سطرًا في التدقيق بالإجراء `chat.conversation.delete` دون نص.
- لا تُكتب صفوف في `request_logs` للمحادثة، لأن هذا الجدول مرتبط بعميل API. المحادثة تستخدم قائمة المزودين نفسها وتراجعهم في `/v1`.

## الاختبارات والبيانات

توليد القفل يتضمن hashes لكل الحزم؛ يثبَّت باستخدام `--require-hashes`. الحزم المضافة في المرحلة الأولى (`argon2-cffi` و`cryptography` وتبعياتهما) نُشرت قبل 2026-11-01، وتم توليد القفل بالخيار `--exclude-newer 2026-11-01` مع تثبيت الإصدارات الموجودة كما هي. شغّل الاختبارات محليًا عبر:

```sh
.venv/bin/python -m pytest -q
```

قاعدة البيانات في حجم Docker المسمى `ai-gateway-v1-data`، ووضع WAL مفعّل. هذا الفرع لا يحتوي على سكربت نسخ احتياطي، فانسخ القاعدة بنفسك قبل الترقية أو الحذف. فترة الاحتفاظ الافتراضية لسجلات البيانات الوصفية 30 يومًا. لا تُسجّل الرسائل أو مفاتيح العملاء الخام أو مفاتيح المزودين في السجلات. نصوص المحادثات موجودة في القاعدة كنص عادي، كما هو موضح في قسم المحادثة.

## الحالة في بيئة التنفيذ الحالية

- نتيجة الاختبارات الكاملة: **332 passed** عند التشغيل من نسخة للفرع في مجلد بصلاحيات مناسبة، وعند التثبيت من `requirements.lock` في بيئة Python 3.12 جديدة. داخل `/projects` في هذه البيئة تفشل 11 من اختبارات قراءة أسرار الملفات، لأن هذا المسار نظام ملفات للقراءة فقط (`ro`) ومجلده بصلاحيات `777`. فحص الصلاحيات يرفض هذه المجلدات، ولم يُخفَّف لتجاوز الفشل.
- اختبارات المحادثة تشمل خادمًا حيًا على TLS، وقطع الاتصال أثناء البث، والإرسال المكرر المتزامن بالمعرّف نفسه، وحفظ الرد غير المتدفق بعد انقطاع العميل مع إعادته بالمعرّف نفسه. اختبارات تسجيل الدخول تتحقق من حدود المحجز والطابور وإلغاء الطلبات على خادم حي تحت ضغط الدخول. اختبارات قاعدة البيانات تشمل ترقية V4 إلى V5 وإعادة التشغيل دون نسخ احتياطي إضافي.
- لم يُختبر أي مزود حقيقي لأن إعداد المزود متروك عمدًا للمستخدم.
- Docker: لم يُبنَ الـ image في هذه البيئة. أمر `docker` هنا يعمل عبر podman، ولا يوجد conmon صالح، فلا يمكن تشغيل حاوية. لم يُنفَّذ `docker compose` ولا `up`.
- يوجد قرار نشر غير محسوم: ربط مضيف loopback مع bind داخلي wildcard، أم host networking لربط حرفي على loopback مقابل عزل شبكي أقل. لم يُختر أحدهما أو يُفعّل.
- الترحيل من V4 إلى V5 اختُبر على قاعدة أنشأها الكود السابق `8b09f2a`، ثم رُقّيت نسخة منها بالكود الحالي. أعادت ثلاث عمليات تشغيل إضافية النتيجة نفسها، وشغّل الكود القديم `main` القاعدة بعد الترقية دون فقد بيانات، مع الملاحظة الواردة في قسم الترقية.
